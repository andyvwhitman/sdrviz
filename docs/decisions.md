## Agent team structure

- **GMUNK lead** (art director): researchers for (a) Oblivion / Tron: Legacy / Tron: Ares work, (b) collaborators and co-designers, (c) outside inspiration, (d) corridor frequency and seed-data research. Produces the creative brief; reviews design work and refined builds.
- **Film graphics designer lead**: screen subagents for Live Ops, History/Stats, Feeds/Banks admin, and Map. Produces SVG/HTML mockups and a design spec (palette, type, components, motion). Iterates with GMUNK.
- **Front-end lead**: build subagents for the Svelte app shell and components, the FastAPI fake backend, and the map. First pass reviewed by the designer, refined passes by GMUNK.

## Deployment architecture (2026-11-16)

Design: docs/deployment-architecture.md. Plan: docs/sprint-2/sprint-2.md.

| # | Topic | Decision |
|---|-------|----------|
| 35 | Where DSP runs | On the node. Each Pi runs a new `sdrviz-node` agent (systemd) next to rtl_tcp: channelize, squelch, NFM demod, Opus encode, spectrum frames, health. Raw IQ (about 25 Mbit/s) never leaves the Pi. The owner reconsidered raw-IQ-to-cloud and re-chose on-node decoding. Refines row 6 (the "sdrviz-agent later" is now). |
| 36 | Node transport | One outbound secure WebSocket per node to `wss://<server>/ws/node` on 443, both directions. Up: Opus audio frames, spectrum frames, key-up/key-down events, health. Down: commands (tune, gain, squelch, restart). Reconnect with backoff, heartbeats. Reuses the `/ws/live` binary frame format (`protocol.py`) plus a node id. No separate HTTP clip upload (only later if backlogs get big). |
| 37 | Audio codec | Opus from node to server (PyAV with libopus, already on the Pi). The server decodes once to the current 8 kHz s16 PCM for browsers, so browser playback is unchanged (iPad Safari safe). |
| 38 | Node enrollment | Settings, Nodes, Add node (name, location, optional channel preset) creates a PENDING node and shows a one-time node key once (text and file): `sdrviz-node1.<base64url JSON {url, node id, enrollment secret (32 random bytes), format version}>`, valid 24 h, single use. `sdrviz-node enroll <key>` or a file in `/etc/sdrviz-node/`. |
| 39 | Node secret | The enrollment exchanges for a permanent node secret that never expires (set and forget for a year or more, never re-auth). The server stores only hashes. Settings can revoke and re-key a node. The server can tell enrolled nodes a new address over the live connection. Settings shows ONLINE / OFFLINE / PENDING with link quality and lag. |
| 40 | Viewer sign-in | Keep the single shared password, hardened: long password from `.env`, login rate limit, lockout after repeated failures. No multi-user accounts, users or roles (no multi-user design yet). |
| 41 | Database | Stay on SQLite, on a Hetzner Volume. Litestream replicates continuously to an S3-compatible bucket. Alembic migrations replace the hand-written `ALTER TABLE` code in `transit/source_store.py` and run at deploy. |
| 42 | Hosting | Hetzner Cloud VM in Ashburn (ash), Docker Compose: Caddy (Let's Encrypt, serves the built Svelte app, proxies `/api` and `/ws`), sdrviz-api (today's app minus radio DSP) and a Litestream sidecar. Private Network from day one, Volume for data, Cloud Firewall allows only 80/443 in, SSH only over Tailscale. The server may later move home with the same Compose file (port forward + dynamic DNS, or a tiny Hetzner relay VM over WireGuard). |
| 43 | Domain and CDN | A subdomain of a domain the owner already owns; DNS stays where it is; one A record. No Cloudflare anywhere (explicitly rejected). |
| 44 | Recording | None. The app records nothing from the real radio (only simulated-day data). Live only. Recording is designed later with the History rebuild (row 34). BE-9 (actual arrivals/departures/passes, row 18) stays deferred in the backlog. Do not write recording tickets. |
| 45 | Channelizer speed | Measured 2026-11-16 on the Pi CM5 (1 core): 8 ch 28% of real time, 24 ch 73%, 48 ch 142%, 91 ch 273%; the matmul channelizer is 81% of the time. Replace it with an FFT-based fast-convolution (overlap-save) channelizer and spread channel work across cores with threads. Acceptance: all 91 AAR channels under 50% of real time on the CM5, output matching today's channelizer within a stated tolerance. First BE ticket. |
| 46 | rtl_tcp service on the Pi | `sdrviz-rtltcp.service` grew to 2.7 GB RSS in 4 days and took 90 s to stop. Fix in the node setup: `TimeoutStopSec=5`, a `MemoryMax` or periodic restart, bind 127.0.0.1 once the agent runs on the Pi. Pi changes are owner-run steps (sudo) with exact commands. |
| 47 | LAN compatibility | The LAN setup keeps working throughout: the backend can use a local rtl_tcp source as today or remote nodes, side by side. |
| 48 | Sprint 2 scope | Refines row 33: sprint 2 is the code-health and systems-design refactor, and its target is the deployment architecture above (node package split, uplink protocol, containers, hardening). Also in: decision 32 typography, dead-code removal, two known bug fixes. Owner-run steps (Hetzner, DNS, Pi sudo, Tailscale) are separate OWNER tickets. Live Ops layout does not change (row 28). Infrastructure as code stays simple: shell and `hcloud` CLI unless the owner chooses otherwise (sprint-2.md question 2). |
| 49 | Sprint 2 questions (provisional) | Answered by the lead while the owner was hands-off, each the recommended option, open to review: launch moves to Sprint 3 (Q1); shell plus `hcloud` CLI (Q2); first key-up wins when two sources hear one channel (Q4); git checkout plus venv on the Pi (Q5). Q3 (backup bucket) and Q6 (server size) stay open for the owner. |
| 50 | Node DSP target | Accepted 2026-11-17: the FFT channelizer's 61% of real time for all 91 AAR channels on the CM5 (4 threads) is good enough; the 50% target is retired. No demod follow-up ticket. Backups (Litestream bucket, decision 49 Q3) are set aside for now. |
| 51 | Server setup tooling | Replaces decision 49 Q2 (2026-11-17). Owner sets servers up often, so it is scripted: `deploy/hetzner/provision.sh` (hcloud CLI: SSH key, private network, firewall, Volume, server; prints the IP; re-runnable) and `deploy/server/setup.sh` (scp'd to the server: Docker, git, clone, .env, start; re-run to update). The Hetzner project and API token are a one-minute console step, since the API cannot create projects. |
| 52 | No Tailscale or VPN | Owner does not want Tailscale or a VPN now (2026-11-17). | 53 | What a node decodes | Owner, 2026-11-17: the server's banks are the source of truth. The spectrum is unaffected (it is the whole tuned window). |
| 54 | Live bank | Owner, 2026-11-17: clicking a channel slot on the Live Ops spectrum or waterfall adds it to the special `bank-live` bank (made on first use; a placeholder frequency `live-chNN` if the table has none on that channel) and activates that bank; alt-click drops it. Audio is on by default: it starts on the first click or key press (browsers allow nothing sooner); the header AUDIO chip is gone, and a small speaker at the bottom right of every screen mutes all audio, remembered per device. |

| 58 | Transcription engine | Owner, 2026-11-17 (option 6): faster-whisper `small.en` on the server CPU with a railroad-vocabulary prompt, behind a replaceable transcriber interface (a hosted API or a Mac worker can replace it by setting). |
